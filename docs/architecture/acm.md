# ACM

## 要件・前提
- CloudFrontをHTTPS終端とするため、ACMを用いてCloudFront用のSSL証明書の作成・更新を管理する
- 独自のSSL証明書を用いたい、という要件はないので、ACMによって作成する
- CloudFrontにアタッチする場合はus-east-1にて作成する必要がある
- ALBとCognito間での通信において、 `authenticate-cognito` のリスナーがHTTPSでないといけない制約があった。そのため、ALBにアタッチするためにACMを用意する。これはALBと同じ東京リージョンに配置する

## 設計

### 構成図

- [docs/architecture/README.md](README.md)参照

### 選定理由
- 自己署名証明書では、自分で有効期限管理や更新を行う必要があり、ブラウザにも信頼されない。だが、ACMではこれが自動化される。
- 他の認証局で発行した証明書はブラウザに信頼される可能性はあるが、証明書の有効期限の管理や更新は自分で行う必要がある。ACM発行の証明書であれば、AWSサービスとの統合、および証明書作成は無料で行うことができ、金銭的コスト面でも優れている

### 通信経路
- 証明書の検証、自動更新のための通信では、ACMとRoute53間で通信が行われる

### セキュリティ設計
- 証明書の更新を自動化することで、HTTPS通信を継続させる
- 秘密鍵はACM内部で処理されるので、漏洩する経路がなく、安全にAWS側で管理される

### 可用性設計
- 特にこちら側で準備できることはない

### コストの見積もり・意識した点
- 証明書の作成、およびCloudFront・ALBとの統合のみになるので、料金は無料
