# ネットワーク

## 要件・前提
- 動的ページを返す部分のVPC内部のネットワーク構成を構築するための指針
- ルートテーブルの役割に応じてサブネットを分割する
- フロント / API（ECS）はECRからイメージをプル、およびCloud Watch Logsへログを送信する
- ECS(API)において、決済サービスは外部APIを呼び出す
- ECS(API)はユーザがアップロードする画像をS3に保存する
- DB層は外部との通信を必要としない

## 設計

### 構成図

- [docs/architecture/README.md](README.md)参照

### 通信経路
- ALBサブネット
  - localのみ、明示的な追加なし
- ECS(フロント)サブネット
  - S3Gateway エンドポイント
- ECS(API)サブネット
  - 0.0.0.0/0 NAT Gateway
- DBサブネット
  - localのみ、明示的な追加なし
- サブネットはルートテーブルの違い、異なる性質のリソースを同じ区分に存在させない、という基準の元分離させる
  - ECS(API)・ECS(フロント)はルートテーブルの違いから、ALB・DBは性質によって分離させる
  - ECS(フロント)は、ECRイメージレイヤーの取得でS3 Gatewayを使うため、ALB・DBとはルートテーブルが異なる


### 選定理由
- IGW
  - ECS(API)から外部APIを呼び出す際に、NAT Gateway→IGW経路で通信をするため、IGWが必要になる
- NAT Gateway
  - 外部APIを呼び出す際に必要
  - 従来のZonalだとサブネットをAZの数だけ用意する必要があり、運用コストが若干上がる。一方で、Regionalはサブネットの作成なしに、自動的にマルチAZ構成で可用性が確保される点で、運用コストの観点から優位。なお、両者の起動時間当たり、および通信料にかかる金銭的コストは同じであるため、Regionalが妥当と判断
  - https://aws.amazon.com/jp/vpc/pricing/
  - ただし、Regionalはプライベート接続に対応しておらず、今回はプライベート接続が不要なため、Regionalを使える
- VPCエンドポイント
  - 下記の通信のためにエンドポイントを用意する
    - ユーザがアップロードする画像をS3へ保存
    - ECSがECRからイメージをプル
    - ECSがCloud Watch Logsへログを送信
  - NAT Gateway + IGW経由の経路で通信を行うことも可能。ただ、仮にECSが侵略され、機密情報を外部に送信される、というケースを考えた場合、それを防ぐには、ルートテーブルで0.0.0.0/0宛の通信をNAT Gatewayのみに向けて出口を1つに絞ったうえで、ECS(API)側のSGのegressルールで0.0.0.0/0:443のような広い許可ではなく、絞った宛先(例: Stripeのみ、マネージドプレフィックスリストで管理)のみ許可するようにすればよい。ただそうなると、上記3つの通信も行うことができなくなり、かつECRなどはマネージドサービスなのでルートテーブルでECRだけをさす、というような指定ができなくなる。よって、ルートテーブルへの追加はNAT Gatewayだけに絞りつつ、かつ3つの通信を維持できるよう、VPCエンドポイントを作成する。なお、合計コストは$60/月と見積もり、追加コストはかかるが、セキュリティリスクを考えればエンドポイントを設けるほうが良いと判断。下記のエンドポイントをAZごとに作成
    - ecr.api
    - ecr.dkr
    - logs
    - S3 Gateway(なお、これは数に含めていないが、理由は金銭的コストがかからないため)
    - $0.014*730時間*6 = $61.32
    - データ通信量にかかるコストは、多めにみても1$にも満たないと思われる
    - https://aws.amazon.com/jp/privatelink/pricing/

### セキュリティ設計
- ルートテーブルに不要なルートを持たせないことで、下記効果を期待できる
  - ALBはIGWへの経路を持たず、インターネットから直接到達できない。DBも同様
- VPCエンドポイントを設けることで、ECSコンテナ侵害時の被害を最小限に抑えることを優先

### 可用性設計
- マルチAZ構成で可用性を確保。なお、AZを増やせば可用性はその分向上するが、金銭的コストが高くなるので、今回は2AZ程度で可用性は問題ないと判断し、2AZ構成とした

### コストの見積もり・意識した点
- 運用コストの観点から、Regional NAT Gatewayを選択。ただし、プライベート接続が不要だからこそできた選択
- VPCエンドポイントを設けることで、金銭的コストが追加されたが、コストの大きさおよびセキュリティリスクを考え、金銭的コストよりもセキュリティを優先し、エンドポイントを追加した
