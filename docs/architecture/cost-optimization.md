# コスト関連

## 要件・前提
- Saving Plansは最低1年以上の継続的利用がある場合のコスト最適化手段として有効だが、現状、そのようなことは想定していないので、使わない
- Budgetはインフラ予算をオーバーしていないか、オーバーしそうならば任意のタイミングでアラートを受け付けることで早期に認識する際に必要となる
- Cost Anomaly Detectionは、これまでのデータをもとに、季節や時間帯も考慮して、コストの使い過ぎを通知してくれるが、今回は事前データがないので、使わない。ただしこれは、あくまで現時点では導入しないだけで、将来的にデータが集まって要望があれば導入も検討している枠となる

### 選定理由
- Budget
  - コスト超過や超過の可能性がある場合に、月末のみではなく、任意のタイミングで通知されることで、事前に大きな予算オーバーを防げる可能性があるため
  - 予算額は、リソースの想定稼働コストの実額に合わせるものではなく、このプロジェクトに割り当てられた月間の許容予算の上限として設定するべきものである。想定コストの実額に閾値を近づけすぎると、アラートが鳴った時点で既に許容額を使い切っており、早期警戒として機能しなくなる。今回は仮の例として$18(約3,000円)を許容上限として設定した
  - 実測値○○%の超過、および予測値○○%を超えそうなときのアラートを設定する。本来ならば、アラート検知してからどれくらいの時間で対処できるのかを考慮したうえで数値を決めるのが望ましいと思われる。例えば、AWSリソースの削減に自社組織以外の判断や許可も含まれるのならば少ない数値になる傾向があり、自組織のみで完結するなら大きめの数値になると予想される。今回は、仮で、実測値50%,80%,100%と予測値100%のアラートを設定する
