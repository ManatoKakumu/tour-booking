# DB

## 要件・前提
- RDSが記載対象
- リレーショナルデータベース、MySQLを選択
- マルチAZ構成で可用性を確保する
- 必要な通信は、ECS(フロント・API)からの読み取り・書き込み、およびプライマリ・スタンバイ間のレプリケーション処理
- B・C間でDBユーザー、GRANT権限を分け、それぞれのユーザーがいじる必要のないテーブルの参照および書き込みを許容させない
- ECS(フロント)は読み込みのみ、ECS(API)は読み込み・書き込みを行う

## 設計

### 構成図

- [docs/architecture/README.md](README.md)参照

### 通信経路
- ECS(フロント・API)からのリクエスト
- プライマリ・スタンバイ間のレプリケーション処理
  - ただし、これは設定するだけで特に通信処理を自身で設定管理する必要はない
- DBサブネットはlocalのみ（明示的な追加不要）で、外部への経路を一切持たない

### セキュリティ設計
- ECS(フロント・API)からのリクエストはECSおよびRDSに付与するSGによって許可する
- B・Cユーザがそれぞれ参照する必要のあるテーブルだけに権限を絞ったDBユーザを各自用意する。フロントは読み込み、APIは読み込み・書き込みを行うが、必要なテーブルにしか権限を持たないようにDBユーザーを4種類作成する。認証情報はSecret Managerを用いる
- データは暗号化して保存するが、転送中の暗号化は行わない
- RDSのパブリックアクセスはブロックし、ECSのみから受け付けるようにする
- deletion_protectionはfalseとする。本来なら誤削除防止のためtrueにすべきだが、今回は個人開発でコスト優先のため、terraform destroyしたら削除されるように、falseとする

### 選定理由
- DBエンジンの選定(RDS vs Aurora)は[ADR-003](../adr/003-rds-vs-aurora-selection.md)を参照
- Secret Managerは認証情報を自動でローテーションするため、仮に漏洩しても長期間に渡る不正アクセスの可能性を下げることが可能
- 保存時は暗号化を必須にすることで、仮にスナップショットが漏洩しても暗号化されているため、情報流出のリスクを下げることができる。スナップショットはIAM権限さえあれば取得できるため、注意する必要がある。なお、暗号化はKMSではなくデフォルトのキーを用いて暗号化する。今回は、誰が複合化したかを知りたい監査的要件がない、一部の人だけに複合化を許可したいユースケースがない、以上から、デフォルトキーを用いた暗号化とし、金銭的コストを抑える
- 転送時には暗号化をしない。転送時の暗号化で防げることは、通信を盗聴された際であるが、そのようなケースは今回の構成において想定したのは、ECSタスクが侵害される場合のみである。ECSタスクが侵害されていれば、DBの認証情報を得てリクエストが可能なので、転送時に暗号化をしても情報を流出できることはない。以上より、転送時の暗号化で守れるケースは少ないと判断し、行わないこととした。
- インスタンスクラスは `db.t4g.micro` とする
  - ストレージとコンピュート層は独立しているため、インスタンスクラスの変更はストレージに悪影響をあたえない
  - マルチAZ構成であるため、インスタンスクラスののちの変更でもダウンタイムは数分程度に収まる想定なので、のちの変更が致命的にはならない
  - 負荷の強さが低い(t3/t4g, micro)、料金が低い(t4g)、という観点でインスタンスクラスを決定
- ストレージタイプはgp3とする
  - 大規模OLTPなどのように高いIOPSを求めているわけではない
  - ストレージ容量は最小制約20GBと想定する。仮にストレージ容量が不足しても自動で拡張してくれるので最初から余裕を持たせる必要はない

### 可用性設計
- マルチAZ構成により、可用性を向上させる
  - AZ障害時にも自動でフェイルオーバーするため、ダウンタイムを最小限に抑えることができる
  - エンドポイントは変わらないため、手動での変更は不要
- backup_retention_periodは0とする。これは暫定で、のちにバックアップについて設計構築するので、その際にあらためて修正する

### コストの見積もり・意識した点
- Secret Manager
  - フロント・API共にB・CでDBユーザーを分けたほうが、想定外のDB値参照・更新を防げるので、それに伴い、シークレットは4つ作成する。別途管理ユーザの認証情報も保存する
  - 10,000件のAPIコールあたり$0.05
    - $0.05と想定
  - 1シークレットあたり$0.40/月
    - $0.40 * 4 + $0.40 = $2.00
  - 合計$2.05/月
- RDS
  - インスタンスクラスは `db.t4g.micro`
    - $0.05/1h
    - $0.05 * 730 = $36.5
  - ストレージタイプは `gp3`
    - $0.276/GB/月
    - $0.276 * 20 = $5.52
  - 合計$42.02/月
- 合計$44.07/月
