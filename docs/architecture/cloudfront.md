# CloudFront

## 要件・前提
- パスベースによって、オリジンを画像保存バケット、静的ページ保存バケット、VPCに分ける
- VPCはCloudFront VPC Origins経由、画像保存バケットおよび静的ページ保存バケットはOAC経由とする
- SSL終端とするため、SSL証明書のインポートが必要
- HTTPはHTTPSへのリダイレクトを採用する

## 設計

### 構成図

- [docs/architecture/README.md](README.md)参照

### 選定理由
- CloudFrontおよびCloudFront VPC Originsを使うことで、ALBへの直接到達経路がなくなる。ALBへの経路はCloudFront VPC Originsのみとなる
- 1つのCloudFrontディストリビューションに集約したのは、ドメインを一つで管理するため。技術的な制約により、1つのドメインは1つのディストリビューションしか持てない

### 通信経路
- 画像取得リクエスト：OAC経由で画像保存S3バケットにルーティング。 `images` で始まるリクエストをルーティング
- 静的ページリクエスト：OAC経由で静的ページ保存S3バケットにルーティング。 `/`, `/about`, `/terms` のリクエストをルーティング
- 動的ページリクエスト：CloudFront VPC Origins経由でVPCにルーティング。上記以外のリクエストをルーティング

### セキュリティ設計
- CloudFront VPC Originsを作成すると、AWS管理のSGが作成されるので、これをALBのSG、Inboundで参照することで、ALBへの経路をCloudFront VPC Origins経由に絞ることができる

### 可用性設計
- 特にこちら側で準備できることはない

### コストの見積もり・意識した点
- インターネットへのデータ転送量
  - 最初の1TB/月は無料
  - 現状のトラフィック的に、1TB/月を超えることはないと想定し、$0とする
- HTTP(S)リクエスト数
  - 最初の1000万件/月のHTTP(S)リクエストは無料
  - 現在のトラフィック的に、1000万件/月を超えることはないと想定し、$0とする
