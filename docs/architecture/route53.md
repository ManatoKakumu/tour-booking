# Route53

## 要件・前提
- 独自ドメインを用いてアプリケーションを運営する
- 独自ドメインはお名前ドットコムで取得しているものをRoute53にて管理する
- ACMと連携し、SSL証明書をDNS検証する。ACMはALB・CloudFront用に用意する両方を指している

## 設計

### 構成図

- [docs/architecture/README.md](README.md)参照

### 選定理由
- ルートドメインをCloudFrontに紐づけたいが、CloudFrontはエッジロケーションに分散しており、特定のIPアドレスを持たない。そのため、ルートドメインを登録するには、Route53独自のエイリアスレコードを使う必要がある。CNAMEは他のレコードとは共存できない制約があり、ルートドメイン配下には、SOA・NSレコードを置く必要があるので、CNAMEレコードでCloudFrontとルートドメインを紐づけることもできず、エイリアスレコードを使う必要がある

### 通信経路
- 実際の独自ドメインによる検索
  - ブラウザ → Route53 → ブラウザ
  - 上記の流れで取得したIPアドレスを使い、ブラウザからCloudFrontへ通信する
- DNS検証
  - ACMとRoute53間での通信が行われる

### セキュリティ設計
- ホストゾーンのレコードを書き換えられるユーザをIAMによって自分のみに絞る
- DNSSECに関しては、いったん見送る。実トラフィックがほぼない段階で、リスクが顕在化する場面がほとんどないと判断したため。

### 可用性設計
- 現段階ではDR計画は考慮していないので、フェイルオーバールーティング+ヘルスチェックは用いない、シングルリージョン構成とする
