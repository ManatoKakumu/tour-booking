# ADR-005: Stripe IPリスト同期のトリガー方式選定

## コンテキスト
- Stripe IPアドレスが変更された際のECS(API)のSG反映について、いくつかの選択肢がある

## 選択肢
- メトリクス検知
- cron式によるLambda実行
- Lambdaの手動実行

## 決定
- Lambdaの手動実行

## 理由
- メトリクス検知
  - CloudWatchのメトリクスフィルタにより、Stripe APIエラーのメトリクスカウントが閾値を超えた場合にLambdaを起動させる
  - Stripe APIエラーは、IPアドレスが変更されたことによるものでけではなく、ほかにも原因が考えられる。その中で、IPアドレスが変更されたことによるものであるかを識別するのが困難
  - 事後対処になるので、アラートが発生するまでの間にエラーを容認することになってしまう
- cron式によるLambda実行
  - 参考文献:https://docs.stripe.com/ips?locale=ja-JP
  - IPアドレス変更の際は、メーリングリストに追加したメアド宛に7日前に検知される
  - 仮にcron式だと、IPアドレス変更タイミングによっては、最大、実行間隔だけIPアドレスが更新されないことを許容することになってしまう。その時間を少なくしたければ間隔を狭めることになるが、その分、無駄なコンピュート資源を使うことになる。
  - メアドに通知が7日前に来るので、それを確認してLambda手動実行で十分と思われる
- Lambdaの手動実行
  - メールアドレスによる検知が可能+資源の無駄使いを避ける、という観点からLambdaによる手動実行を選択
