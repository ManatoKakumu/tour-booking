# ADR-004: コンピュート起動方式の選定(ECS vs Lambda vs EC2)

## コンテキスト
- 今回はコンピュート層にECSを選択したが、ほかの選択肢も考えられる

## 選択肢
- ECS
- Lambda
- EC2
- EKS

## 決定
- ECS(Fargate)

## 理由
- Lambda
  - リクエスト処理時のみに稼働し、ECSよりも時間当たりのコストは下がると思われる。ただし、Lambdaにした場合はDB接続の上限数に達して一部で接続できなくなる可能性があるので、RDS Proxyを使うことも考慮したコスト計算のほうが望ましいと思われる
  - ただ、懸念点として、Lambdaによるコールドスタートでレイテンシが高くなる可能性がある。プロビジョンド容量を設定し、コールドスタートの問題は解決できるが、結局リクエスト増大によってプロビジョンド容量を超えるLambdaが起動される場合、一部でコールドスタートの可能性がある
  - ユーザ体験を考慮すれば、コールドスタートはなるべく避けたほうがいいと判断した
- EC2
  - 今回のアプリケーションにおいて、OSを自分で設定したい用途がなかった
  - なので、OS管理は自身で責任を持つべきではないと判断した。なお、ECS Fargateであれば、OS管理はAWSに任せられる
- EKS
  - そもそもKubernetesの知識がまだ私にはないこと、および今回のアプリケーションであれば、ECSでも十分に構築できると判断した
- 以上より、ECSを選択した
