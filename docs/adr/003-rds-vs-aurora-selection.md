# ADR-003: DBエンジンの選定(RDS vs Aurora)

## コンテキスト
- 今回は、リレーショナルデータベースということだが、候補としてRDS, Auroraがある

## 選択肢
- RDS
- Aurora

## 決定
- RDSとする

## 理由
- フェイルオーバーはRDSは60-120秒、Auroraは30秒とAurora有利ではあるが、RTO/RPOの数値を詳しく決めていないので、Auroraを選ぶ根拠としては弱い
- 処理面では、Auroraの方が優位。RDSのリードレプリカでは、更新ログをリードレプリカの数だけ送信しなければならないので、数が増えていくほど特にプライマリの負荷が高くなる。一方で、Auroraのリードレプリカは、共有ストレージを使っているので、RDSの同期処理よりもパフォーマンスがよい。ただ、初期段階においては、トラフィック量が読めないので、Auroraにする根拠としては少し弱い
- 処理面ではAuroraが勝るが、金銭的コストではRDSの方が優位
- 仮に処理面の改善をしたい場合にも、下記方法にてRDSからAuroraへと移行ができ、かつダウンタイムも最小限に抑えることができる
  - RDSのリードレプリカとしてAuroraを構築し、起動出来たらAuroraをライターインスタンスに昇格させる。後にRDSを終了させる
- 以上より、RDSを選択するが、これはあくまで最初の話であり、将来ずっとRDSにする、という意味ではない。必要に応じて、Auroraへの移行も検討はしている、という意味合い

## 結果
- 実トラフィックがほぼなく、Auroraが優位になる状況(リードレプリカの追加が必要になるなど)は起きていない。一方で、負荷の実測値も取れていないので、どの時点でAuroraへ移行すべきかの判断材料は乏しいままである
- フェイルオーバーは、この構成では未実施。別途、検証用の環境でRDS Multi-AZのフェイルオーバーを試した際は、約90秒であった。フェイルオーバーを1分以内に収める必要が出てきた場合は、Auroraへの移行を検討する
